## 阶段结论与系统链路

**截至T05，搭建的是确定性的桌面Workflow；T07/T08在其上接入了受限Pi分析。** 提醒、权限、取消与保存仍由程序负责，模型负责从文本识别任务并提出字段建议。

```text
本地Workflow：录入 → 校验 → SQLite → 排序/状态检查 → 提醒策略 → 用户完成或推迟 → 保存
智能录入：通知文本 → 后台RPC → 沙箱Pi/Flash → MCP只读查重 → 草稿校验/时间规则
         → 用户确认任务清单 → 选择重复候选 → 检查字段 → 应用事务保存 → 本地Workflow
```

| 阶段 | 完成的工作 | 为什么这样设计 | 核心技术 | 需要掌握的问题 | 对问题的理解 |
| --- | --- | --- | --- | --- | --- |
| 环境准备 | 依赖隔离、版本固定、Qt DLL修复 | 让安装可复现 | venv、依赖约束 | 为什么不能依赖机器上碰巧能运行的环境？ | 不同依赖版本可能改变行为，需保存运行条件与验证证据。 |
| T01：任务数据 | 添加、读取、完成；编辑/删除仍待做 | 数据独立于窗口 | 数据模型、SQLite、事务 | 为什么重启后任务仍在？ | 数据库保存事实，窗口负责展示。 |
| T02：桌面交互 | 面板、托盘、隐藏恢复 | 保持低成本使用 | Qt事件循环、生命周期 | 为什么关窗口还能提醒？ | 隐藏不等于退出；退出、关机或睡眠后不能继续定时检查。 |
| T03：截止规则 | 排序、30分钟前/逾期提醒、推迟10分钟 | 提示风险并避免重复打扰 | 时间比较、状态机、幂等 | 为什么不能每次检查逾期都提醒？ | 逾期条件持续成立，需保存已处理阶段与推迟状态。 |
| T04：Windows集成 | 全局热键、单实例、可选登录自启 | 快速录入，避免重复提醒 | RegisterHotKey、IPC、HKCU Run | 为什么重复启动应唤醒已有窗口？ | 多实例会争抢热键、重复调度；锁与健康检查是不同问题。 |
| T05：提醒系统 | 强度、工作时段、免打扰、逾期例外、持久化冷却 | 平衡避免遗漏与打扰 | 定时调度、状态管理、SQLite、自动化测试 | 为什么提醒必须独立于Agent运行？ | 因为定时提醒属于确定性任务。如果完全依赖大模型，就可能出现调用延迟、成本增加以及执行不稳定的问题，因此应由本地调度器负责，Agent只参与需要智能判断的任务。 |
| T07：受限Pi接入 | RPC、MCP、进程内适配、AppContainer、固定模型通道、真实工具调用 | 保留智能能力，同时限制资源和动作 | Agent Loop、Tool Calling、RPC、MCP、SID/ACL、Job、Broker | 为什么工具调用成功还不等于完整验收？ | 还要核验身份、参数、真实返回、最终结果和清理。只读连接不等于进程沙箱；普通权限成功不能证明沙箱有效。 |
| T08：智能录入 | 最多5项任务、查重、清单/字段确认、建议标注、原子保存、取消恢复 | AI给建议，用户决定事实 | Schema、Provenance、Draft State、事务、运行代次 | 合法JSON为什么不能直接保存？ | 格式正确不证明语义正确；须核对原文、确定性规则及用户确认。重复只是候选，丢弃新增不删除旧任务。 |
| T06/T09及以后 | 跨时区、每日计划、文档/第三方接入、评估尚未完成 | 按真实需求逐步增加 | UTC/IANA时区、Planning、授权、Evaluation | 何时需要Skill？ | 先评估现有Workflow和Agent的缺陷，再判断Skill是否能稳定改进；不为每个功能先建Skill。 |

## T07术语对应关系

| 专有名词 | 在FocusPilot中的含义 |
| --- | --- |
| Harness | 管理模型运行、上下文、工具、预算、取消与权限边界的执行环境。 |
| API / Tool Contract | 程序接口与参数/结果契约；不是MCP的同义词。 |
| RPC | Python与Pi之间的会话通信，不天然承担权限控制。 |
| MCP | 发现和调用工具的协议；可以使用自定义Transport承载。 |
| Extension / Adapter / Transport | Pi扩展注册工具；适配器转换调用；传输实现承载协议消息。 |
| Sandbox / Broker / TCB | OS限制进程资源；权限代理审查受控访问；宿主服务仍是需信任和测试的代码。 |
| Workflow / Agent Loop | 前者执行确定性规则；后者由模型根据上下文选择工具、观察结果并继续判断。 |
| Fail Closed / Human-in-the-Loop | 边界不成立就停止；影响正式任务的保存由用户检查确认。 |

## 当前可观察证据

- [真实Pi进程内MCP](T07_PI_INPROCESS_VALIDATION.json)：目录/激活集合仅两个工具；查询、取消、超时与清理通过，不代表原生stdio问题修复。
- [真实模型分析](T08_MODEL_ANALYSIS_VALIDATION.json)：两次模型连接、实际MCP查重、两项草稿，虚构库未变。
- [可见窗口交互](T08_GUI_VALIDATION.json)：清单确认、重复候选选择、字段检查、保存后重读、运行中取消均通过；使用QTest操作本进程窗口，不冒充用户亲自验收。
- 明确的“明天17点”由本地规则换算；“明天下午”保持缺失并让用户补充。模型不能自行决定17点。
- 登录自启/注销及系统通知实际送达仍待系统场景验证，不能用接口调用或单元测试代替。
