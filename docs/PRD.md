# FocusPilot 产品需求文档（PRD v0.1）

## 1. 核心用户问题

多项任务并行时容易遗漏；任务记录的操作成本高；仅靠被动打开 Todo 软件不足以发现风险；被打断后难以恢复工作上下文。产品不承担诊断或医疗干预，只提供执行辅助。

## 2. 产品定位

Windows 本地优先的主动待办执行助手。**主要入口是桌面悬浮面板与快速捕获；Pi Agent 负责智能规划，不取代提醒与存储逻辑。** 外部文档、日历、飞书/邮件等数据源仅在明确授权后按需连接。

## 3. 已确认需求

1. Windows 桌面常驻、可选置顶、系统托盘和可退出。
2. 每日/每周待办；关注重要程度、DDL、项目进度及执行顺序。
3. 高优先级任务能够主动提醒，支持确认、完成、稍后提醒。
4. 低摩擦记录；以后支持自然语言直接添加。
5. 可以授权读取指定文档或第三方应用，但不强制依赖飞书。
6. 产品开发使用 Codex，最终的智能规划能力采用 Pi Harness。

## 4. 推荐默认策略（可依据真实使用调整）

- 主界面最多突出 3 个核心任务，其余折叠显示。
- 对紧急任务主动提示，对普通任务默认仅在面板显示；避免通知疲劳。
- 所有 DDL 默认是用户输入的硬约束，AI 只能建议调整，未经确认不能修改。
- 本地可离线运行；调用外部模型必须由用户开启并配置。
- 优先保证「记录—展示—完成—重新提醒」闭环，再增加自主规划。

## 5. MVP 不做

不自动阅读整个硬盘、不自动发送邮件或消息、不自动修改第三方文档、不强制接入飞书、不承诺关机时仍有提醒、不做医疗行为评估。

## 6. 成功指标（验证指标，不是已实现成绩）

- 使用期间的关键任务遗漏数、按时完成率。
- 创建任务平均交互步数。
- 强提醒后是否出现有效操作（开始/推迟/完成）。
- 用户认为无意义的提醒比例。
- 桌面 UI 的启用率和主动查看次数。

## 7. 需求待确认项

- 强提醒边界：持续置顶、系统横幅、声音、按任务等级配置哪几种？
- 快速捕获输入：热键文字优先，是否需要语音？
- 本地文档权限的白名单范围和外部 AI 使用政策。
- 日历空闲时间、个人精力偏好和工作时段的计划规则。

这些问题**不阻塞当前本地 MVP**；在触及该功能的 Ticket 开始前做决策即可。
