# Pi Harness 离线模拟测试计划

状态：T07离线控制与本地MCP服务均已实现；当前完整149条通过。控制底座首轮45条，MCP适配本轮另增29条（含3条命名空间测试）。未调用真实Pi或模型，T08场景仍待实现。设计依据：[Harness 设计草稿](PI_HARNESS_DESIGN.md)。

## 目标与方法

先验证应用的执行控制与权限边界，再验证真实模型能力。离线协议模拟不能证明模型任务拆分准确，也不能证明特定 Pi 版本完全兼容。

- **Test Double（测试替身）：** 替代真实外部组件的总称。
- **Fake Pi（假 Pi）：** 未来实现的可控子进程，读取协议命令、发送指定消息，可延迟、分段、失败；不是另一个智能体。
- **Assertion（断言）：** 检查可观察行为，例如确认界面未打开、保存调用次数为零、原文未丢失；不只检查内部状态字符串。
- **Invariant（不变量）：** 任意合法或异常事件顺序下，都必须保持的边界。
- 时间用可推进的单调测试时钟，子进程测试用有界同步，不依赖长时间 sleep。

## 必须保持的不变量

1. 用户未确认当前版本并保存前，Agent 分析不得改变正式任务；模型文本不构成确认。
2. 已取消、超时或被替换的运行，不得打开确认界面、覆盖新输入或使用旧草稿。
3. 接受请求与自然语言“完成”不能代替运行终态、有效结果和应用校验。
4. 数据库读取失败不能被解释为没有重复；所有正式任务查询都遵守最小权限。
5. Agent 故障不能阻塞 Qt 主线程或停止本地提醒。取消失效与后台资源回收是不同阶段。

测试只能证明所覆盖路径；只读连接测试通过不能替代整个进程的权限隔离检查。

## T07：离线接入底座场景

| 编号 | 输入/事件序列 | 必须观察到的结果 |
| --- | --- | --- |
| R01 | 接受 prompt → 尚无终态 | 仍为进行中，不宣称分析成功，不进入任务保存 |
| R02 | 接受 → 最终错误/进程退出 | 显示可恢复错误，原文保留，保存次数为 0 |
| R03 | agent_end → 自动重试 → 最终 settled | 不在中间结束事件放行结果；按最终终态判断 |
| R04 | 启动时立即发送事件，命令响应随后到达 | 监听不漏消息，结果不因迟到响应回退为进行中 |
| R05 | 同一 JSON 被拆成多个字节段，多个 JSON 合并在一次读取中；stderr 混有诊断 | 完整重建协议消息；诊断不作为协议解析；损坏记录按约定报错 |
| R06 | 连续两次点击分析 | 仅发出一份活跃分析请求；不隐式排队 |
| R07 | 接受 → 用户取消 → 旧结果/settled 到达 | 输入界面立即恢复原文，旧结果不展示；后台停止与清理可独立完成 |
| R08 | A 取消 → A 清理完成 → B 开始 → A 已排队的 UI 回调到达 | B 的文本、状态和结果不被 A 覆盖 |
| R09 | 持续小量输出或重试，超过总时限 | 仍触发总超时，不因每个 token 无限续期；不静默重新提交模型请求 |
| R10 | 停止请求无响应或 Pi 提前退出 | 有界清理自己启动的子进程；不触及其他进程；之后可新建运行 |
| R11 | 工具收到未知参数、SQL、路径、伪造确认/运行身份 | 应用拒绝越权输入；不读额外范围、不写任务 |
| R12 | 合法只读查询执行/失败 | 仅读测试数据库必要字段；成功与失败可区分；查询前后任务内容不变 |
| R13 | Pi 等待/错误期间，测试任务达到提醒时间 | Qt 事件仍被处理，现有提醒检查能够执行；不是只检查计时器对象存在 |
| R14 | prompt 响应为 handled/queued，或不支持的协议形态 | 不无限等待，不假装成功；保留输入并按约定取消/报错 |

R08 的迟到消息可能来自已经排队的回调，不要求假进程退出后仍能向管道写入。命令 ID 与本地运行身份分开检查，不假造官方事件都自带请求 ID。

## T08：草稿业务场景（后续实现时执行）

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| D01 | 有效工具批次 + 正常收敛 | 数量与清单来自应用认可的最新批次；没有用户操作不写库 |
| D02 | 正常收敛但无草稿工具结果，或草稿/查重失败 | 不开放自动草稿确认入口；错误与零任务结果不同 |
| D03 | 未完成同名、已完成同名、同名不同日期、同批同名 | 严格遵守已确认规则；展示候选不自动丢弃；已完成项默认排除 |
| D04 | 明确/缺失/含糊日期、建议重要程度、估计耗时、字段来源矛盾 | 校验与来源标注正确；缺失日期可保留草稿，但须由用户处理 |
| D05 | 用户丢弃一份新草稿或选择仍然新增 | 更新保留数量，不修改数据库旧任务 |
| D06 | 草稿修订、修改标题/截止时间、旧确认重放 | 旧版本确认失效；相关修改重查候选，不能跳过确认门槛 |
| D07 | 模型声称用户已确认，重复点击保存，数据库写入失败 | 模型不能触发保存；同一保存动作不得重复创建；失败不能显示成功；写入一致性策略在 T08 定义 |
| D08 | 有效工具批次后用户取消，随后模型正常结束 | 不打开表单、不写库；停止不是对已提交事务的撤销承诺 |

## 测试分层与环境

| 层次 | 验证内容 | 不能据此宣称 |
| --- | --- | --- |
| 状态/契约单元测试 | 事件序列、输入约束、失效结果处理 | 真实管道和 Windows 窗口正常 |
| 假子进程集成测试 | JSONL 分帧、响应关联、异常退出和停止 | 真实模型或真实 Pi 兼容性通过 |
| Qt 自动测试 | 后台协作、界面状态、提醒事件继续执行 | 用户实际看到系统横幅 |
| Windows 实际操作 | 取消恢复、重试、界面响应 | 任意模型输出都正确 |
| 真实 Pi/模型评估 | 固定版本兼容性、任务提取质量、成本和延迟 | 仅凭一次成功就完成全部验收 |

全部离线用例使用临时数据库和虚构文本，不读取正式 APPDATA 数据，不联网。只读测试暂停独立提醒写入，比较任务逻辑内容；提醒并行测试允许现有 Workflow 的预期阶段更新，不把该更新误判为 Agent 越权写入。
